# Career OS — Environment Setup

This is the Phase 0 scaffold: a working FastAPI backend + React (Vite) frontend
that can talk to each other, with a database, ready for Phase 1 (job search).

Already done for you in this scaffold:
- Backend runs on SQLite by default — **no Docker/Postgres required to start.**
- `/health`, `/profile` (GET/POST), `/jobs` (GET) endpoints working.
- Frontend hits the backend on load and shows status + job count.
- `.gitignore` set up so you don't accidentally commit `.env`, the DB file, or `node_modules`.

---

## 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Open `.env` and set your real `GEMINI_API_KEY` (needed from Phase 2 onward — not required just to run the health check). Get one at https://aistudio.google.com/apikey.

Gemini covers both the LLM calls (matching reasoning, resume tailoring, cover letters, interview prep) **and** embeddings (`text-embedding-004`), so it's the only AI key this project needs — no separate embedding provider.

Run it:
```bash
uvicorn app.main:app --reload
```

Check it's alive: open http://localhost:8000/health — should return `{"status":"ok"}`.
Interactive API docs (auto-generated by FastAPI): http://localhost:8000/docs

### Switching to Postgres later (optional)
If you decide you want Postgres instead of SQLite:
1. `docker run --name career-os-pg -e POSTGRES_PASSWORD=devpass -e POSTGRES_DB=career_os -p 5432:5432 -d postgres`
2. `pip install psycopg2-binary` (add it to `requirements.txt`)
3. In `.env`, set `DATABASE_URL=postgresql+psycopg2://postgres:devpass@localhost:5432/career_os`

No other code changes needed — `app/db.py` reads the URL and adapts.

## 5. Phase 1 — Profile + Job Search (done)

**Profile:** Go to the "Profile" tab in the frontend, fill in your info and resume text, click Save. Stored locally in the `user_profile` table — nothing is sent anywhere until a later phase explicitly calls the LLM.

**Job search (Greenhouse):**
1. Find the board token for companies you're targeting — it's the slug in their job board URL: `boards.greenhouse.io/<token>`.
2. Either:
   - Type comma-separated tokens into the "Jobs" tab search box and click **Run Search**, or
   - Set `TARGET_COMPANIES=token1,token2,...` in `.env` and leave the search box blank.
3. Jobs are fetched, HTML descriptions cleaned to plain text, deduped by URL (re-running sync won't create duplicates), and stored.

Endpoints added this phase:
- `GET /profile`, `POST /profile`
- `GET /jobs`
- `POST /jobs/sync` — body `{"board_tokens": ["stripe", "notion"]}` or `{}` to use `.env` config

Note: Greenhouse's public API needs no auth key, but some companies' boards can 403 automated requests depending on network/IP — if a sync fails for a token, check the `errors` field in the response before assuming your code is wrong.
